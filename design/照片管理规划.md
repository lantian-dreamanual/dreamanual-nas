# 照片模块 · 功能规划

2026-10-18 立项。设计稿见同目录 `照片原型.html`（可切换 7 屏 + 组件板，勾「标注」看逐点说明）。接口事实的出处：`docs/接口结论.md` 第七节第 4 条（2026-10-11 实测）与 `experiments/shuffle-lab/out/apiinfo_all.json`（API 地图全量）。

## 一、先更正一条旧结论

`产品定义.md` 里「不做相册」的理由写的是「接口只能按目录树浏览」。这条只对了一半：

- **共享空间（`SYNO.FotoTeam.*`）确实没有相册接口** —— `Browse.Album` 不在 API 地图里，这部分判断成立；
- **个人空间（`SYNO.Foto.*`）接口是全的** —— `Browse.Album` v5 / `ConditionAlbum` v4 / `Timeline` v6 / `Person` v3 / `Geocoding` / `GeneralTag` / `Favorite` v2 都在地图里。当时「只能按目录树浏览」的印象来自这台机的个人空间是**空的**（0 相册、0 照片、`Browse.Folder` 回 602），接口全但没数据。

现状是：**有内容的那一侧（共享空间）恰好只能按时间轴 / 目录 / 人物 / 地点浏览，没有相册；相册接口在有数据的另一侧**。所以「不做相册」应改写成「共享空间没有相册接口，相册功能随个人空间的数据出现」——这不是砍功能，是功能跟着数据走。

## 二、能力地图（接口 × 空间 × 实测状态）

| 能力 | 共享空间 | 个人空间 | 实测状态 |
|---|---|---|---|
| 时间轴 | `Browse.Timeline` v6 | `Browse.Timeline` v6 | ⚠️ 未实测（返回结构未知） |
| 条目列表 | `Browse.Item` v7 | 同左 | ✅ 实测（`additional` 只认 JSON 数组，回逗号串报 120） |
| 缩略图 | `Thumbnail` v2 GET | 同左 | ✅ 实测（`unit_id` ≠ 条目 `id`，四参数缺一不可，只能 GET，会话用 FileStation 那把） |

| 标签 | `Browse.GeneralTag` | 同左 | ⚠️ 未实测 |
| 相册 | **无接口** | `Browse.Album` v5 / `ConditionAlbum` v4 | ✅ 实测（个人空间 0 个） |

设计原则从这张表直接推出来：**侧栏条目按「当前空间有什么」渲染，不做灰掉的假入口**。共享空间没有相册与收藏，这两行在共享空间就不出现（设计稿相册屏里那行常驻说明是给用户的一句解释，落码时可以只在空态文案里说）。

## 三、信息架构

```
外壳侧栏 220          内容区侧栏 200           主区
┌──────────┐   ┌────────────────┐   ┌──────────────────────┐
│ 听歌      │   │ 共享空间         │   │ 页头（维度名 + 统计）   │
│ 照片 2486 │ → │  时间轴 / 最近添加 │   │ 工具条（分段/密度/搜索）│
│ 文件管理  │   │  文件夹          │   │ 网格 / 相册格 / 人物格  │
│ 系统状态  │   │ 智能分类         │   │ 状态栏                │
│ ── 设置   │   │  人物 / 地点 / 标签│   └──────────────────────┘
└──────────┘   │ 个人空间         │
               │  时间轴 / 相册 / 收藏│      播放条 68 常驻（含查看器）
               └────────────────┘
```

- 空间切换用工具条左侧的**分段控件**（共享空间 / 个人空间），切过去内容区侧栏整列换掉。空间是「看哪一边」的决定，放侧栏分组里表达不动这个层级。
- 页头标题跟当前维度走（时间轴 / 相册 / 人物……），副行报「空间 · 张数 · 文件夹数 · 最近索引」，与曲库页「全部曲目」同构。
- 设计稿里 2 486 张、38 个文件夹等数字是**示意样本**，用来撑网格与分组的规模；这台机实测共享空间只有 10 项。

## 四、新增落点（需进 design-system.md 第八节的）

已有组件全部照既有规格复刻（内容区侧栏、页头、工具条、分段、搜索框、上传行、空态、Toast、弹窗），真正新的只有六件：

1. **照片块（tile）**：正方形、圆角 `r-8`、间距 `s6`、密度三档列宽 94 / 128 / 168（布局值）。选中**不套列表行浅底轨** —— 块里是图像，浅底会被盖住；改成内描边 2px `accent-fill` + 图像压暗 32%，失焦描边转 `accent-line`。悬停压暗 18% + 左上浮勾选框（14，`DmCheckbox`）。
2. **日期分组标题**：`t13` / 600 / `ink-2`，右侧张数 `t11` / `ink-3`，上距 `s20` 下距 `s8`。它是页面主线，比内容区侧栏的分组标题（11/700/ink-3）大一号。
3. **视频角标**：右下时长，10 号等宽数字，底 `rgba(10,10,10,.72)` 白字、`r-4`。
4. **多选浮动操作条**：只在选择模式出现，浮在状态栏上方居中。`panel-2` + 发丝描边 + `r-10` + `shadow-toast`、高 44；动作走紧凑档 28；删除排最右、危险语义只进图标与字色。
5. **查看器**：收侧栏、独占整窗，播放条照旧保留（与沉浸模式同一口径）。顶栏 52（返回 / 文件名 / 序号 / 动作组），大图 contain 居中 `r-12` + `shadow-modal`，右侧信息栏 300 可收起（字段全来自 `Browse.Item` 的 `additional`），切换靠 `←` `→`，`Esc` 关闭。胶片条第一版不做 —— 2 486 张规模要虚拟化，`←` `→` 与网格点击够用。
6. **相册卡 / 人物卡**：相册卡 168 起、4:3 封面 `r-8`、卡面 `panel-2` `r-12`；人物卡 88 圆头像 + 名字 + 张数。条件相册与普通相册同一张卡，副行标「按规则」。

## 五、分批落码

| 批 | 内容 | 依赖 |
|---|---|---|
| 1 · 只读骨架 | 空间探测 → 时间轴网格（`Browse.Item` + `Thumbnail`）+ 日期分组 + 懒加载 + 查看器（大图 / 信息栏 / `←` `→`）+ 空态 | `Timeline` 结构待实测，先可全用 `Item` + `sort_by=takentime` 兜底 |
| 2 · 浏览维度 | 文件夹（复用文件管理的树）、最近添加、人物 / 地点 / 标签（各一屏，数据有没有空态兜底）、搜索（提交式） | `Person` / `Geocoding` / `Search` 实测 |
| 3 · 写操作 | 上传（拖入 + 进度行）、删除（确认弹窗）、收藏、加入相册、新建相册、原图下载、视频播放（`Streaming`） | `Upload.Item` / `Download` / `Favorite` 方法名全部待探 |

冒烟通路照惯例加 `DM_PHOTOS=<指令>`，核对完 reset。

## 六、落码前必须实测的六条

探测脚本放 `experiments/shuffle-lab/`（照 `sortprobe.py` 的做法）：

1. `Browse.Timeline` v6 的返回结构：分组是按天给数组还是给年月日字段，`offset/limit` 怎么翻页；
2. `Download` 与 `Streaming` 的方法名与参数（`download` 已知回 117）；
3. `Upload.Item` v8 的参数形态、是否分段、进度怎么拿；
4. `Browse.Person` / `Geocoding` / `GeneralTag` 有没有真实数据（没有就第一批不落这三屏）；
5. `Favorite` v2 的读写方法；
6. `Search.Search` v7 的参数与是否也有假空（文件管理的 `FileStation.Search` 连吃 6 次假空的前科，重试上限 12 的口径直接沿用）。

## 七、风险与待确认

- **规模**：实测共享空间只有 10 项。如果真实库就是这个量级，日期分组与懒加载是过度设计，密度三档也可以砍；设计稿按普通家庭库（数千张）画，等用户往里放照片后规模假设自然成立。
- **EXIF 明细**（机身 / 镜头 / 光圈 / 快门 / ISO）服务端是否随条目下发未实测，信息栏第一版只落确认有的字段，取不到的整行不占位。
- **共享链接**（`PublicSharing` v1 / `Sharing.Passphrase`）未规划进第一批，设计稿里只留了入口位。
- 产品定义第 1.1 节与第九节「验证状态」的「相册」两行要随本规划一起改。
